Core Doctrine

Evidence Before Assertions.

Most AI coding agents act like overconfident interns: they modify a file, declare “I have fixed the issue!”, and leave you to discover broken syntax, failed tests, and silent regressions. minicode prohibits unverified claims.

Conventional AI Agents

Hallucinated Completion

  • ✕ Claims code works based purely on generative probability.
  • ✕ Leaves broken imports and silent type errors in your repo.
  • ✕ No reproducer guard: never proves a bug existed before "fixing" it.
  • ✕ Pollutes your working tree directly with unchecked code.
“I’ve fixed the database connection error for you!” (Compiler: 4 errors, 0 tests run)
minicode Standard

Strict Verification Barriers

  • ✓ Verification Barrier Engine: Blocks completion until tests and linters pass.
  • ✓ Reproducer Guard: Writes a failing unit test proving the bug before implementing the fix.
  • ✓ AST Syntax Barrier: Tree-sitter verifies zero syntax errors prior to saving diffs.
  • ✓ Disposable Git Worktrees: Unverified code never touches your active working branch.
“Verified: 8 tests passed, 0 compiler warnings. Exit code 0 recorded.”

Confined Execution

Linux Kernel-Level Sandboxing.

An autonomous agent with write access shouldn’t have free rein over your machine. minicode binds execution with Linux Landlock LSM, enforces strict workspace confines, redacts sensitive secrets, and stores keys in an encrypted vault.

Active Kernel Guard

Landlock LSM Confinement

Linux Security Module syscall sandboxing prevents path traversals. Even if an agent requests /etc/passwd or /tmp, the kernel rejects it with EACCES.

Automated Scrubber

Secret & Token Redactor

Automatic regex redactor strips AWS keys, GitHub tokens, Bearer headers, and database URIs before they reach LLM prompts or disk logs.

Encrypted Keystore

Local Credentials Vault

Zero plaintext secrets in config files. API keys and deployment credentials live encrypted in your local OS keyring or encrypted vault.
